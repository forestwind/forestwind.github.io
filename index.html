01개요

타입 추가와 연결 코드로 적용프로젝트는 아이템 타입과 연결 코드만 작성
CSV 기반 데이터 작업수치는 CSV, 리소스는 DataAsset. 에디터 툴로 같이 확인
쿡 누락 검사패키징에서 빠질 데이터 폴더를 에디터에서 미리 경고
적 처치프로젝트가 드롭 요청
드롭확률에 따라 상자 생성
획득닿으면 획득 · 알림 표시
인벤토리같은 아이템은 묶어서 보관
아이템 사용클릭하면 효과 적용

02시스템 구조

프로젝트는 플러그인에 요청만 하고, 플러그인은 결과를 이벤트로 알리기만 함. 플러그인이 프로젝트 코드를 참조하지 않아 다른 프로젝트에도 그대로 적용 가능.

드롭 인벤토리 · 조회 UI · 입력 에디터 툴 요청 (함수 호출) 알림 (이벤트)

03구현 내용

데이터

데이터 구조

  • DataTable: 수치·텍스트 데이터 (CSV → Reimport)
  • DataAsset: 언리얼 리소스 (아이콘, GameplayEffect). CSV에 에셋 경로를 넣지 않아 Reimport해도 리소스 연결 유지
  • 두 데이터는 ItemId로 연결. 타입이 달라도 겹치지 않는 번호
  • 아이템 타입·등급: GameplayTag. 프로젝트에서 행·리소스 구조체와 DataAsset을 상속해 새 타입 추가
  • 타입별 DataAsset이 DataTable 참조·리소스·타입 태그를 묶음. Project Settings에 등록
  • 조회 서브시스템: 시작 시 등록된 타입을 읽어 ItemId로 바로 찾도록 정리
에디터 툴

아이템 뷰어

  • Editor Utility Widget. ItemId 기준으로 DataTable 행과 DataAsset 리소스를 한 표로 표시
  • 리플렉션으로 부모 → 자식 구조체 순서로 모든 필드 표시. 타입·필드를 추가해도 뷰어 수정 없음
  • 열별 폭 조절, 기본 칸 폭 설정
드롭

드롭 · 픽업

  • 드롭 테이블: 한 줄 = 드롭될 수 있는 아이템 하나 (DropGroupId, ItemId, 확률, 개수 범위)
  • 줄마다 따로 확률을 계산해 0개부터 여러 개까지 드롭
  • 드롭 시점은 프로젝트에서 결정. DropGroupId와 위치만 넘기면 드롭 (현재는 적 사망 시 요청)
  • 픽업: 넘긴 위치 주변에 흩어서 생성, 플레이어가 닿으면 획득
인벤토리 · UI

인벤토리 · 획득 알림

  • UI는 프로젝트에서 구현, 플러그인의 변경 알림(이벤트)을 받아 표시
  • 같은 아이템은 MaxStack까지 한 칸에 쌓고, 넘치면 새 칸(SlotId) 생성
  • 인벤토리 창: 등급별 테두리 색, 아이템 클릭 시 사용
  • 획득 알림: 여러 개를 주우면 차례로 표시
GAS 연동

아이템 사용

  • UI에서 아이템을 클릭하면 컨트롤러가 이벤트를 보내고, 사용 어빌리티(ULAUseItemAbility)가 처리
  • SlotId 조회 → 소비 타입 확인 → 1개 제거 → 리소스에 지정된 GameplayEffect를 자신에게 적용
  • 플러그인은 SlotId 조회·제거만 처리, 효과 적용은 프로젝트에서 처리

04트러블슈팅

패키징 빌드에서 아이템 데이터 누락

현상
에디터 플레이에서는 정상이지만 패키징 빌드에서는 아이템·드롭 데이터가 빠질 수 있음
원인
Project Settings에 등록한 에셋은 경로 문자열(Soft 참조)로만 저장되어, 맵·BP에서 참조된 에셋만 포함하는 쿡 대상에 들어가지 않음
해결
데이터·픽업 폴더를 쿡 대상에 등록하고, 누락된 폴더가 있으면 에디터에서 경고 로그 출력. Windows 패키징 빌드에서 데이터 로드·드롭·획득·사용 동작 확인

아이템 뷰어 목록에 이전 아이콘 잔상

현상
아이템 뷰어의 ListView에서 행 위젯이 재사용될 때 다른 아이템의 아이콘이 남아 보임
원인
빈 Soft 참조로는 이미지 브러시가 지워지지 않고, 비동기 로딩 결과가 행이 다른 아이템으로 재사용된 뒤에 도착
해결
아이콘을 동기 로딩으로 바꾸고, 아이콘이 없으면 자리는 유지한 채 숨김 처리. 이후 만든 인벤토리 칸·획득 알림에도 같은 방식을 처음부터 적용

05전투 시스템

GAS 기반 근접 전투. 공격 판정·콤보·무기·사망 규칙은 직접 작성.

공격 판정

  • 노티파이 스테이트로 판정 구간 지정, 판정 처리는 캐릭터별 컴포넌트에서 실행
  • 무기 메시에 설정한 충돌 박스를 읽어 판정에 사용
  • 휘두른 궤적을 회전 각도에 따라 나누고, 구간마다 SweepMultiByChannel로 검사해 큰 동작도 빈틈 없이 판정
  • 판정은 "맞음"만 알리고, 데미지는 어빌리티가 결정
GitHub에서 보기

콤보

  • 콤보 전체를 어빌리티 하나로 처리, 공격 중 누른 입력은 버퍼에 저장
  • 몽타주 블렌드 아웃 때 버퍼에 입력이 있으면 다음 단계, 없으면 종료
  • 단계마다 몽타주와 기본 데미지를 한 묶음으로 설정(ComboSteps), 데미지는 맞은 동작의 몽타주로 단계를 찾아 적용
GitHub에서 보기

무기 데이터

  • 무기를 액터 대신 데이터 에셋(ULAWeaponData)으로 정의: 메시·부착 소켓·어빌리티 세트
  • 장착 컴포넌트가 메시를 충돌 없이 부착하고 무기 어빌리티 세트 부여
  • 무기는 데이터 에셋 하나와 메시의 충돌 박스 설정만으로 추가 가능

GAS 기본 기능

Gameplay Ability System

ASC·AttributeSet, 네이티브 GameplayTag

어빌리티 세트

어빌리티와 Has Duration·Infinite GameplayEffect를 기능별 세트로 묶어, 캐릭터·무기 데이터에서 필요한 세트만 골라 조합

데미지 계산

Execution으로 공격력·방어력 반영, 메타 속성으로 체력 처리

사망 처리

체력 0 이벤트로 사망 어빌리티 발동, Infinite GameplayEffect로 사망 상태 유지

입력

Enhanced Input, 태그 기반 어빌리티 입력

데이터 로딩

적 캐릭터 데이터 비동기 로딩

코드 흐름 (권장 순서)

  1. 데이터 기반 — LIItemRowBase.h, LIItemDataAsset.h (행 구조체, 타입별 DataAsset)
  2. 조회 — LIItemSubsystem (시작 시 데이터 읽기, ItemId 조회, 쿡 경고)
  3. 드롭 — LILootSubsystem → LIItemPickup (확률 계산 → 픽업 생성 → 획득)
  4. 인벤토리 — LIInventorySubsystem (스택, 칸 번호, 변경 이벤트)
  5. 프로젝트 연결 — LAEnemyCharacter (사망 → 드롭 요청), LALIConsumeItem (소모품 타입), LAUseItemAbility (아이템 사용)
  6. 전투 — LAMeleeComboAbility (콤보) → LAMeleeTraceComponent (공격 판정) → LAExecCalc_Damage (데미지 계산) → LADeathAbility (사망)
